# BUG-007

**Bug ID:** BUG-007
**Title:** Customer `Last Seen` timestamp is not updated
**Severity:** Medium (provisional — confirm during investigation)
**Status:** Open
**Date:** 2026-07-28 (added to tracker). Original report date: Unknown — not recorded in repository.

---

## Description

The Customers sheet `Last Seen` column is not updated on flows documented to
update it, so `Last Seen` does not reflect the customer's most recent activity.

## Business Impact

Customer-record correctness degrades: staff and any downstream logic relying on
`Last Seen` (recency, follow-up prioritization) see stale values. Not directly
customer-facing, but it undermines the customer data the system is meant to keep.

## Expected Behaviour

- [`docs/data-model/customers.md`](../docs/data-model/customers.md): `First Seen`
  and `Notes` are preserved across rebookings, while `Last Seen`, vehicle fields,
  and `Last Service` reflect the most recent booking.
- [`docs/tools/reschedule_appointment.md`](../docs/tools/reschedule_appointment.md):
  the Customers write updates `Last Appointment ID` and `Last Seen`.
- [`docs/tools/cancel_appointment.md`](../docs/tools/cancel_appointment.md): the
  Customers record is updated after cancellation (`Last Seen`, notes context).

## Actual Behaviour

Reported: `Last Seen` is not updated. Not independently reproduced in this
documentation pass. The specific flows affected (booking, reschedule, cancel,
and/or post-call notes) are not yet established.

## Steps to Reproduce

Unknown — requires investigation. Proposed starting point (not yet executed):
perform a booking (and separately a reschedule and a cancellation) for a known
customer and compare the `Last Seen` cell before and after on each flow.

## Investigation Status

Not started. Open — investigation required.

## Root Cause

Unknown — requires investigation.

Candidate areas to examine (unconfirmed — starting points only):
- The Customers-sheet write nodes on booking, reschedule, and cancel paths
  (whether `Last Seen` is in the written column mapping).
- The post-call `Update Customer Notes` node
  (`docs/workflows/post-call-processing.md`), which timestamps notes and may or
  may not touch `Last Seen`.
- The preservation logic that keeps `First Seen`/`Notes` across rebookings — is it
  inadvertently preserving (not updating) `Last Seen`?

## Acceptance Criteria

- `Last Seen` is updated to the most recent activity on the documented flows (at
  minimum booking and reschedule per the tool docs).
- `First Seen` and `Notes` remain preserved across rebookings.
- Customer writes remain idempotent create-or-update operations
  (`Customer ID = CUST-<digits>`, `DECISIONS.md`).

## Engineering Notes

Confirm the exact set of flows that must update `Last Seen` against the deployed
artifact (`production/workflow-v26.9.json`) and the tool contracts before a fix;
the tool docs assert `Last Seen` updates on reschedule and after cancellation, so
those are the first paths to verify.

## Regression Requirements

To be defined once the root cause is confirmed. A guard would assert that
`Last Seen` advances on each activity flow while `First Seen`/`Notes` are
preserved.
