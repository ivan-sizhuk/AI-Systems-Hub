# INV-014 — matchService weak-match confidence guard

**Related bug:** [BUG-014](../bugs/BUG-014.md) · **Status:** Confirmed · **Date:** 2026-08-19

## Method
Instrumented and executed the deployed V27.8 `matchService` and the full estimate pipeline against weak-match, named-request, self-diagnosis, mixed, and catalog inputs.

## Findings
- "hard to start in the morning", "can't get it to start", "having trouble starting", "it barely starts" → starter **$549** (invented price).
- Root cause: stem collapse — `stem("start") === stem("starter")`; a single key-word hit scores 2 + 2 rarity = 4, clearing the `>= 2` threshold. Symptom and request score **identically**, so min-score (A) and min-margin (B) guards are structurally incapable.

## Designs compared
- **A min score / B min margin:** rejected (cannot separate start vs starter — identical scores).
- **C reject generic single-token:** rejected (reintroduces a symptom lexicon → whack-a-mole).
- **D surface corroboration:** recommended.
- **E (D + unmatched→diagnostic):** out of scope for BUG-014 (changes the `$0` fallback path).

## Fix validated (Design D)
Corroboration guard in `Estimate Job Ballpark`. Regression (139 cases + boundary suite): invented-price **4 → 0**; catalog/self-diagnosis/mixed regressions **0**; all named requests priced; all boundary/self-diagnosis cases **unchanged from V27.8**.

## Honest scope
The guard eliminates the **weak/ambiguous-match class** (part word not spoken). A symptom that explicitly names its own component ("battery keeps dying") is a strong, corroborated match and remains the symptom classifier's responsibility (currently handled). The absolute word "NEVER" is therefore **not** claimed; the stated acceptance criterion — no specific repair price from a weak/ambiguous match — **is** met.
