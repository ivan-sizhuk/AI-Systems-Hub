# INV-012 — Estimate classifier: undiagnosed leaks & transmission complaints

**Related bug:** [BUG-012](../bugs/BUG-012.md) · **Status:** Confirmed · **Date:** 2026-08-15

## Method
The live `Estimate Job Ballpark` code (byte-verified against the running V27.5 workflow) was executed in isolation against the live Services catalog. No live workflow execution; no calls placed.

## Confirmed behavior (before fix)
`diagnosticOnly = isVagueSymptom && !hasNamedService`:
- "coolant leak" → `diagnosticOnly=false`; matched `radiator` ($549) or `coolant_flush` ($149) by the model's category guess.
- "catalytic converter" → `false`; `catalytic_converter` ($849) — treated as a named service (left as-is; doc conflict noted separately).
- "transmission is acting up" → `false`; `transmission_fluid` ($199) in every variant, including a stray `serviceCategory="transmission_fluid"` guess.

## Root cause
"leak" is not in `symptomOnlyKeywords`; components that co-occur with leaks (coolant/radiator/oil/power-steering/fluid) are in `namedServiceKeywords`, so `hasNamedService` forces `diagnosticOnly=false`. Bare "transmission" is in neither set, so the scored matcher lands on `transmission_fluid`.

## Fix (V27.6, Option 2)
A narrow diagnostic-dominant gate on `serviceRaw`: any leak → diagnostic unless an explicit replacement verb + a named component is present; transmission complaint → diagnostic unless fluid/flush/service/change is named. Validated by 18 logic-simulation assertions (all pass) against the generated V27.6 artifact.

## Distinction limitation (recorded)
The estimate tool inputs are free-text only (`service`, `serviceCategory`, `serviceDetails`); there is no diagnosis-state field. The classifier therefore cannot robustly separate an undiagnosed leak from a previously-diagnosed repair; Option 2 uses an explicit-replacement-verb heuristic as a proxy. A robust fix requires a new tool input (separate ticket).
