# INV-013 — Estimate classifier: residual symptom-family under-coverage

**Related bug:** [BUG-013](../bugs/BUG-013.md) · **Status:** Confirmed · **Date:** 2026-08-17

## Method
The live V27.6 `Estimate Job Ballpark` code (byte-verified against the running workflow) was executed in isolation against the live Services catalog over a matrix of symptom, named-service, explicit-replacement, self-diagnosed, mixed, adversarial, and leak/transmission inputs. No live workflow execution; no calls placed.

## Confirmed behavior (V27.6, before fix)
- 11 critical inputs returned a specific repair price for an undiagnosed symptom (e.g. car won't start → starter $549; AC not blowing cold → a/c compressor $899; steering wheel shakes when I brake → wheel alignment $129).
- 16 moderate inputs returned a `$0` book-a-visit with no diagnostic recommendation.
- Across a 32-input symptom sweep: 12 specific prices, 19 `$0`, 1 diagnostic.

## Root cause
The gate only routed a narrow `symptomOnlyKeywords` set plus leak and the literal word "transmission" to diagnostic; all other symptom families fell through to `hasNamedService`/`matchService`.

## Fix (V27.7)
Broadened diagnostic-dominant gate: `diagnosticOnly = isSymptom && !explicitNamedRequest`. Validated by a 118-case two-sided regression: 0 invented repair prices for symptoms; 0 named services turned diagnostic; self-diagnosed named parts preserved as priced.

## Recorded limitation
"sounds like <part>" is treated as a suspicion (priced), so "car sounds like a diesel" lands on the `$0` book-a-visit fallback rather than an explicit diagnostic. No wrong price is produced. Matcher-confidence hardening (BUG-014) and pricing disambiguation (BUG-015) remain separate.
